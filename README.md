# Изи Хост — v0.1.0 (исходный релиз)

Android-приложение для локальной раздачи статических сайтов с телефона.

## Что входит в v0.1.0
- Русское имя приложения и иконка из предоставленного изображения.
- Переработанная карточка сервера: кнопки действий расположены ровной сеткой 2×2, одинаковая высота, иконки и короткие подписи.
- Открытие локального сайта в браузере.
- Копирование LAN-ссылки для устройств в той же Wi-Fi сети и отображение LAN-адреса.
- Сохранение выбранной корневой папки, проекта и порта в настройках приложения.
- Раздача HTML, CSS, JavaScript, изображений, шрифтов, аудио и видео.
- Потоковая передача файлов вместо чтения всего файла в оперативную память.
- Проверка сегментов пути против `..`, обратных слешей и NUL.

## Сборка
1. Откройте папку `EasyHost-main` в Android Studio.
2. Используйте JDK 17 и Android SDK 35.
3. Выполните Gradle Sync и `Build > Build APK(s)`.

В исходном архиве намеренно нет Gradle Wrapper. Сборку следует выполнять в Android Studio с установленным Android Gradle Plugin 8.7.3.

## Как разместить сайт
Выберите корневую папку, например `Documents/Host`. Каждая вложенная папка — отдельный сайт. Внутри сайта нужен `index.html` или `index.htm`. Запустите проект. Для ПК в той же Wi-Fi сети используйте отображаемый LAN URL, например `http://192.168.1.20:8080`.

## Ограничения v0.1.0 — важно
- **PHP пока не исполняется.** `.php` распознаётся, но сервер отвечает `501 Not Implemented`. Для PHP нужен встроенный PHP-CGI/runtime под Android ABI и безопасный мост из HTTP-запроса к интерпретатору. Это не решается добавлением одного Maven-пакета.
- **WebSocket-чат пока не включён в исполняемую сборку.** Статические файлы с интерфейсом чата откроются, но обмен сообщениями между устройствами требует серверного WebSocket/API-модуля.
- **Сервер пока живёт в процессе Activity.** Это не полноценный Android Foreground Service; сворачивание/выгрузка приложения может остановить сервер. Не закрывайте приложение во время тестирования.
- LAN IP берётся из Wi-Fi интерфейса. Некоторые Android-версии/сети могут ограничивать получение адреса или связь между клиентами.
- Подключённая папка сохраняет URI-разрешение Android; если пользователь отзовёт доступ, папку потребуется выбрать заново.

## Технические заметки
NanoHTTPD обслуживает HTTP и потоковую выдачу файлов. PHP runtime требует отдельной нативной интеграции. Например, актуальный TrueAsync Android runtime поставляет статические библиотеки и заголовки, а native-bridge требует Android NDK и сборку JNI-библиотеки; это полноценная нативная задача, не готовая drop-in зависимость. См. документацию проекта: https://github.com/true-async/native-bridge и https://github.com/true-async/releases.

NanoWSD — отдельный модуль NanoHTTPD для WebSocket. Его можно встроить в общий серверный слой, но нельзя просто запустить второй сервер на том же порту, не объединив HTTP и WS маршрутизацию. См. https://github.com/NanoHttpd/nanohttpd.
